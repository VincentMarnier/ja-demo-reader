# M7: release, licensing and sharing audit

**Status:** Shareable development release.
**Scope:** Make the repository safe to publish, license it, document the
human-facing product, and audit the tracked files for game data, personal
information and build artifacts.

## 1. Repository audit

Checked with `git ls-files`, `.gitignore` and a full-tree search:

| Check | Result |
|---|---|
| Retail game assets (`*.pk3`) tracked | **None** |
| Demo files (`*.dm_26`, `*.dm_25`, etc.) tracked | **None** |
| Maps (`*.bsp`), models, textures, sounds tracked | **None** |
| Built engine (`*.wasm`, `openjk.x86.js`) tracked | **None**; `app/public/engine/*` is ignored |
| `app/dist`, `node_modules`, Vite/CMake/build trees tracked | **None** |
| Screenshots, videos or captured demo frames tracked | **None** |
| Logs, `.env`, credentials, API keys, tokens | **None** |
| OpenJK upstream content vendored | **No**; it is a pinned git submodule |
| Unlicensed bundled third-party code | **None**; deps are declared in `app/package-lock.json` |

The worker mounts user-selected PK3s read-only with `WORKERFS`; demos and
added map PK3s are written to the writable `MEMFS`. The legacy OPFS asset copy
was removed in M9 Phase 3. The repository contains no game data and no demo
recordings.

## 2. Personal and development data

The release pass removed environment-specific data from the repository:

- Absolute home-directory paths were replaced with `$JKA_ROOT`, `$HOME`, or a
  required environment variable.
- Environment-specific development evidence paths were changed to the generic
  `/tmp/jka-demo-player/...` working directory.
- Test demo names, player handles and score-strip screenshots in the docs were
  replaced with generic names (`demo.dm_26`, `PLAYER A`, `POV player`).
- `scripts/verify-demo.mjs` now requires `ASSETS_DIR` and `DEMO`/`DEMO_FILE`
  instead of a hard-coded user path.
- `scripts/stage-engine.sh` requires an explicit build directory.
- Build scripts default to `$TMPDIR`/`/tmp` and `$HOME/emsdk`, not a private
  machine path.

Historical milestone documents still contain evidence timestamps, generic
`/tmp` artefact names and retail asset sizes. They contain no game data, user
accounts, secrets or personal paths. Git commit metadata still carries the
local author name/email; configure the repository identity before publishing if
you want a different public attribution.

## 3. Licensing

- The project is released under **GPL-2.0-only**; see [LICENSE](../LICENSE).
- The engine is OpenJK (GPLv2) plus this project's GPLv2 patches. The pinned
  upstream commit is recorded in `references/OpenJK` and
  `engine/README-PORT.md`.
- `app/package.json` declares `GPL-2.0-only`.
- Third-party components are listed in
  [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). The runtime app uses
  React/ReactDOM (MIT); the build uses Vite/TypeScript and related dev tools.
- No proprietary Jedi Academy assets are distributed. Users must own the game.
- The README includes the non-affiliation/trademark disclaimer.

## 4. Build and deployment

- Engine build is reproducible from the pinned OpenJK commit and the patches
  `0001`–`0009` in `engine/patches/` using Emscripten 6.0.1.
- `build-mp-wasm.sh` installs the Emscripten JPEG/PNG/SDL2 ports when needed.
- `.github/workflows/deploy-pages.yml` builds the engine and app and deploys
  `app/dist`; game assets are never part of the deployment.
- Pages source must be set to **GitHub Actions** in the repository settings.
- The app has no server component and no upload endpoint.

## 5. Privacy/security

- No analytics, telemetry, remote logging or external asset requests.
- Engine networking is disabled in the Emscripten build (`NET_Init` skipped),
  `cl_allowDownload` is `0`, and demo files are read locally.
- The file picker is local; the app never writes to the user's game folder.
- OPFS/IndexedDB caches are local browser storage and can be cleared from
  Settings.
- The wasm engine runs in the page with the browser's normal sandbox; it has no
  filesystem access beyond the staged MEMFS/OPFS data.

## 7. Known limitations at release

- Audio remains disabled.
- Remote health/armor are not in the base snapshot. The summary scan recovers
  them from the team overlay, the duel health configstrings, the recorded
  client's playerState and damage events (exact for teammates/self, inferred
  elsewhere). Remote saber stance comes from `entityState.fireflag`; the wire
  field is two bits, so dual/staff are corrected from clientinfo for the
  followed player.
- Objective scores from mod-specific server commands are not parsed.
- First shader initialization can be slow on software WebGL; the browser GPU
  shader cache helps on later runs.
- Keyframes are per-engine/session. A reload with a cached summary triggers the
  parse-only scan to rebuild them; it does not reload the map.
- Backward/forward seek and Restart are warm only within the same map. A demo
  that changes maps takes the full map/cgame load. No multi-map demo exists in
  the local test set, so that path is not release-validated.
- Added-map PK3 demos are supported and scanned/played in the app, but mods
  with extra cgame globals or unusual server commands are not broadly tested.
- There is no asset cache; the legacy OPFS tree is removed once on startup.
- A seek to the very first snapshot can briefly show that snapshot's
  gamestate score/timer until the next configstring updates arrive.
